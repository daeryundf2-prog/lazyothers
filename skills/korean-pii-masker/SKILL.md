# Korean PII Masker — 한국형 개인정보 비식별화

법원 제출본·공문서·분석 보고서에 남은 개인정보를 결정적으로 마스킹한다.
체크섬 검증까지 수행하며, 처리 통계는 스크립트가 산출한다(SSOT).

## 핵심 도구

```bash
python ${PLUGIN_ROOT}/scripts/mask_korean_pii.py 증거설명서.md -o 제출용.md --report 비식별리포트.md

# 주민번호·전화만
python ${PLUGIN_ROOT}/scripts/mask_korean_pii.py 데이터.csv --types rrn,phone
```

## 마스킹 규칙

| 유형 | 원본 | 마스킹본 |
|---|---|---|
| 주민등록번호 | 901212-1234561 | 901212-1****** |
| 전화/휴대폰 | 010-1234-5678 | 010-1234-**** |
| 계좌번호 | 123-45-678901 | 123-45-****** |
| 이메일 | hong@example.com | h**@example.com |

- 주민번호는 **체크섬 검증**을 병행한다. 체크섬이 틀린 형식값도 마스킹하되
  리포트에 "불일치 N건"으로 표시해 원본 확인을 유도한다(오탐 경보).
- 날짜(2024-01-16)는 계좌번호로 오탐하지 않도록 판별해 유지한다.

## 한계 — 반드시 고지

- **사람 이름·주소는 탐지하지 못한다** (사전 없이는 불가능). 이름 비식별화가
  필요하면 사전 기반 라이브러리([ko-pii](https://github.com/Marker-Inc-Korea/ko-pii),
  MIT — 룰·체크섬·가명 Vault 33카테고리)를 보강으로 검토하고, 최종 제출본은
  사람이 1회 더 훑어야 한다.
- HWPX/HWP 원본 서식을 보존한 마스킹은 kordoc MCP의 `redact_document`가
  담당한다. 텍스트 레이어는 본 스크립트, 서식 문서는 kordoc으로 분업.

## 워크플로

1. `generate_evidence_doc.py` → 증거설명서 생성
2. `mask_korean_pii.py` → 제출본 비식별화 + 리포트
3. 제출 전 `audit_evidence_integrity.py`로 해시 대조(비식별본은 원본과 해시가
   다르므로, 어느 쪽 해시를 증거설명서에 기재했는지 혼동하지 말 것 — 원본 해시
   기재가 원칙, 비식별본은 별도 관리)
